# QA Agent Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** CLI em TypeScript que lê casos de teste em linguagem natural de um Excel, executa no navegador com Playwright (compilação em cache + autocorreção), e gera um relatório HTML de evidências com screenshots.

**Architecture:** Reader → (Compiler just-in-time com cache) → Runner → Healer (só em falha) → Judge → Reporter. O LLM fica atrás de `LLMProvider`; prints e texto passam por `masking` antes de sair da máquina. Estado de cada run vive em `runs/<runId>/` (manifest incremental + evidências).

**Tech Stack:** Node 20+, TypeScript (strict, ESM), Playwright (Chromium), vitest, zod 4, exceljs, commander, yaml, `@anthropic-ai/sdk`, `@axe-core/playwright`.

**Spec:** `docs/superpowers/specs/2026-10-16-qa-agent-design.md`

**Decisões do plano que refinam a spec (sem mudar seu intento):**
- Compilação é *just-in-time* por passo: um passo sem cache é compilado com o snapshot da página no estado em que o Runner a deixou; com cache, o LLM não é chamado.
- `LLMRequest.schema` é um schema **zod** (os provedores o convertem em JSON Schema); a validação e a retentativa usam o mesmo schema.
- Mapeamento de colunas, `allowedHosts`, `minConfidence` e `maxHealAttempts` vivem em `qa-agent.config.yaml`; a aba `Config` do Excel é lida e mesclada por cima.
- A URL base pode ser sobrescrita por `--base-url` (necessário para rodar o Excel sintético contra o app local de teste).

## Global Constraints

- Playwright com Chromium, execução em série.
- Locators por papel e nome (`{ role, name }`); nunca CSS/XPath nas ações compiladas.
- Status de passo: `pass | fail | healed | skipped`. Status de caso: `pass | fail | needs-review | blocked`. Em dúvida, **nunca** `pass`; o Healer nunca marca `pass`.
- Chave de cache = hash(texto do passo + `Dados` (template, sem resolver) + URL de origem + versão do compilador + `provider.id`).
- Heal: no máximo `maxHealAttempts` (padrão **2**) por passo. Orçamento de LLM por `--max-llm-calls`.
- Segredos só em `.env`/cofre do CI; nunca em Excel, cache, manifest, logs ou relatório (valores secretos viram `••••`).
- Imagens só chegam ao LLM como `MaskedImage`. Campos de senha sempre mascarados.
- O Runner só navega em `allowedHosts` (padrão: host da `url_base`).
- Evidências: `runs/<runId>/evidence/<idSeguro>/<NN>-before.png|after.png`, com `idSeguro = id.replace(/[^A-Za-z0-9_-]/g, "_")`.
- Tokens visuais (aproximados, não verificados): navy `#10384F`, azul `#0091DF`, azul claro `#00BCFF`, aprovado `#89D329`, reprovado `#D9363E`, revisão `#F5A623`, bloqueado `#8A97A0`. Status sempre com ícone + texto.
- Relatório autocontido: sem recursos externos (nenhum `http(s)://` em `src`/`href` de assets), pilha de fontes do sistema.
- Mensagens da CLI e do relatório em português.

## Review Focus

1. **Excel com casos intercalados ou passos fora de ordem** (mesmo ID em linhas não contíguas, `Passo nº` embaralhado): deve agrupar por ID e ordenar por `Passo nº`. (Task 4)
2. **Excel sem aba `Casos`, vazio, ou com variável `{{X}}` sem valor no `.env`:** erro claro listando o que falta, nunca crash nem execução parcial silenciosa. (Tasks 4, 5)
3. **Valor digitado em campo de senha vindo de literal na coluna `Dados`:** não aparece em texto de log, manifest nem relatório (`••••`). (Tasks 5, 13, 21)
4. **Página com texto de prompt injection ou redirecionamento para host fora da lista:** o Runner só executa ações do schema e falha explicitamente ao sair de `allowedHosts`. (Task 13)
5. **ID/título com acentos, `/`, `<script>` ou texto de passo muito longo:** nomes de arquivo sanitizados e HTML do relatório escapado (sem XSS). (Task 21)
